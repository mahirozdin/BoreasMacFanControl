# Boreas Master TODO — P0 → P8

- **Plan version:** 1.0
- **Baseline date:** 2026-07-31
- **Source blueprint:** v1.1 (frozen: `docs/blueprint/boreas-blueprint-v1.1.md`)
- **Overall status:** P0–P5 complete. **The fan write path is real and proven on this machine:** the helper takes a fan over, drives it (999→1548 rpm in 0.5 s), hands it back, and every failure path returns the hardware to firmware — `kill -9` in 1.0 s, a frozen client via watchdog in 15.8 s, both measured with the fan actually spinning. P4 is closed: the manual slider drives the hardware through the safety chain with rpm-exact tracking, the state machine logs every transition, and `make smoke` reproduces the whole hardware proof in one command (sleep leg attended-only, release blocker B5). The engine's signal path is in: a curve that cannot be non-monotone, hysteresis whose lock is a proven plateau, an asymmetric rate limiter, and the step-model comparison that keeps ADR 0010 measurable. P5 is closed: the composed engine runs against frozen golden scenarios, the published schema validates through the types, a broken file can only fall back, and migration is proven lossless. P6 has begun: the design system is in — the two continuous colour scales live as tested Core maths (continuity, monotone warmth and red-exclusion are properties, not intentions), red belongs to panic/error alone, and both appearances are render-proven. **The product now cools automatically:** the menu bar panel's profile picker drives the P5 engine end to end — selecting Balanced was measured driving the fan along the Balanced curve on this machine, selecting System hands the hardware back — with fan fill gauges and collapsible grouped temperatures on the design-system scales. The status item is configurable (layouts, compact mode, mini chart, driving/override marks) and warns when the menu bar squeezes it out — the concealment decision is tested Core maths, and the crowded-bar case was proven by flooding the real menu bar. The main window is in: monitoring with temperature and fan charts on one shared time axis, a sortable sensor table, and a control tab that says which profile is active and why, shows all five safety layers, and lets a manual override take the wheel for a set time — proven on hardware to hand back to the *engine*, not the firmware. **The signature interface is in:** the curve editor draws its four live layers, and its edits reach the fans within a cycle — measured, 1838 → 4021 rpm on an edited curve. The monotonicity constraint is enforced by clamping rather than by rejection, so no sequence of edits can produce an invalid curve; 10 000 hostile ones are thrown at it in the tests. **Settings now persist:** the configuration file is read at launch and written back — profiles, curves, sensor corrections and the panic threshold all survive a restart, a broken file can only fall back, and a hostile one is clamped by the types. **The diagnostics tab is in, and its honesty rule is enforced by the type rather than by careful writing:** there is no "faulty" verdict to reach for, a concern cannot be raised without offering explanations beside it, and a test refuses six accusing words across every code path. On this machine the fan tracked its targets to within 69 rpm — the false-positive risk tested rather than assumed. **Global shortcuts work without the accessibility permission the project promised never to request**, and the render evidence now draws real system controls, retiring a limitation that had been carried through five phases. **The product speaks Turkish**: 327 strings in a String Catalog built from the compiler's own extraction, with a gate that refuses a half-translated language and refuses an accusing word in *any* language. **Profile triggers are editable**, and building that editor exposed that a standing manual selection had been vetoing every trigger — automatic mode is now reachable and proven on hardware. **The interface answers to a user who is not looking at it**, and the pass that proved it found a real defect: five of the seven chart series colours were below the 3:1 WCAG asks of a line that *is* the data, so the palette was retuned by brightness alone — hues untouched, worst case now 3.78:1 — and the luminance band that makes 3:1 possible against both appearances at once is a constant the tests re-derive rather than trust. The menu bar item no longer signals "I am driving your fans" by tint alone; it says so, from a tested `Core` value. Three gate rules hold the rest, each proven by deliberate violation, and one of them turns "honours Reduce Motion" from a promise into a fact by refusing any animation that does not ask. Two limits are recorded rather than papered over: the accessibility tree cannot be read in-process without the permission this project refuses to request, and Dynamic Type is inert on macOS — which makes the pseudo-locale test the only check invariant Y3 has. 218 tests, 11 gates. Next: P6.13.

## The "do the next task" algorithm

1. Run the `BOOT.md` health snapshot. **If a gate is red, fix that first.**
2. Find the lowest numbered incomplete phase in the status summary above.
3. Are that phase's dependencies `DONE`? If not, move to the dependency.
4. Pick the first unchecked atomic task in the phase.
5. If the task depends on a manual task, **skip it, take the next one.** A blocker never freezes the work.
6. Do the task. **Run** the verification commands and read the output.
7. Pass the `AGENTS.md` §8 Definition of Done list.
8. Close the session: checkbox + status summary + run log — **in the same change**.

- **ID:** P2
- **Status:** `DONE`
- **Depends on:** P1
- **Goal:** Unprivileged monitoring working, with **the abstraction layer in place from day one**.

- [x] **P2.04 — `LiveSensorSource`.** Temperature reading through the HID sensor services. Prove on real hardware that a sensor list and sane values come back.

```
| YYYY-MM-DD | <session> | P<n>.<nn> | DONE/BLOCKED | <what was done and WHY it was done that way; unexpected findings> | <commands + PASS/FAIL/NOT RUN+reason> | <files> | <risk> | Next: P<n>.<nn> |
```

**Rules:**
- Never hesitate to write `NOT RUN` — "I wrote it, it probably works" makes the system a liar
- Record the unexpected finding **with its evidence**, so the next session does not fall into the same trap
- `Handoff` must be a single, definite task
