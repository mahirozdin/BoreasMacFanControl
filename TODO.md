# Boreas Master TODO — P0 → P8

- **Plan version:** 1.0
- **Baseline date:** 2026-07-31
- **Source blueprint:** v1.1 (frozen: `docs/blueprint/boreas-blueprint-v1.1.md`)
- **Overall status:** P0–P5 complete. **The fan write path is real and proven on this machine:** the helper takes a fan over, drives it (999→1548 rpm in 0.5 s), hands it back, and every failure path returns the hardware to firmware — `kill -9` in 1.0 s, a frozen client via watchdog in 15.8 s, both measured with the fan actually spinning. P4 is closed: the manual slider drives the hardware through the safety chain with rpm-exact tracking, the state machine logs every transition, and `make smoke` reproduces the whole hardware proof in one command (sleep leg attended-only, release blocker B5). The engine's signal path is in: a curve that cannot be non-monotone, hysteresis whose lock is a proven plateau, an asymmetric rate limiter, and the step-model comparison that keeps ADR 0010 measurable. P5 is closed: the composed engine runs against frozen golden scenarios, the published schema validates through the types, a broken file can only fall back, and migration is proven lossless. P6 has begun: the design system is in — the two continuous colour scales live as tested Core maths (continuity, monotone warmth and red-exclusion are properties, not intentions), red belongs to panic/error alone, and both appearances are render-proven. **The product now cools automatically:** the menu bar panel's profile picker drives the P5 engine end to end — selecting Balanced was measured driving the fan along the Balanced curve on this machine, selecting System hands the hardware back — with fan fill gauges and collapsible grouped temperatures on the design-system scales. The status item is configurable (layouts, compact mode, mini chart, driving/override marks) and warns when the menu bar squeezes it out — the concealment decision is tested Core maths, and the crowded-bar case was proven by flooding the real menu bar. The main window is in: monitoring with temperature and fan charts on one shared time axis, a sortable sensor table, and a control tab that says which profile is active and why, shows all five safety layers, and lets a manual override take the wheel for a set time — proven on hardware to hand back to the *engine*, not the firmware. **The signature interface is in:** the curve editor draws its four live layers, and its edits reach the fans within a cycle — measured, 1838 → 4021 rpm on an edited curve. The monotonicity constraint is enforced by clamping rather than by rejection, so no sequence of edits can produce an invalid curve; 10 000 hostile ones are thrown at it in the tests. **Settings now persist:** the configuration file is read at launch and written back — profiles, curves, sensor corrections and the panic threshold all survive a restart, a broken file can only fall back, and a hostile one is clamped by the types. **The diagnostics tab is in, and its honesty rule is enforced by the type rather than by careful writing:** there is no "faulty" verdict to reach for, a concern cannot be raised without offering explanations beside it, and a test refuses six accusing words across every code path. On this machine the fan tracked its targets to within 69 rpm — the false-positive risk tested rather than assumed. **Global shortcuts work without the accessibility permission the project promised never to request**, and the render evidence now draws real system controls, retiring a limitation that had been carried through five phases. **The product speaks Turkish**: 327 strings in a String Catalog built from the compiler's own extraction, with a gate that refuses a half-translated language and refuses an accusing word in *any* language. **Profile triggers are editable**, and building that editor exposed that a standing manual selection had been vetoing every trigger — automatic mode is now reachable and proven on hardware. **The interface answers to a user who is not looking at it**, and the pass that proved it found a real defect: five of the seven chart series colours were below the 3:1 WCAG asks of a line that *is* the data, so the palette was retuned by brightness alone — hues untouched, worst case now 3.78:1 — and the luminance band that makes 3:1 possible against both appearances at once is a constant the tests re-derive rather than trust. The menu bar item no longer signals "I am driving your fans" by tint alone; it says so, from a tested `Core` value. Three gate rules hold the rest, each proven by deliberate violation, and one of them turns "honours Reduce Motion" from a promise into a fact by refusing any animation that does not ask. Two limits are recorded rather than papered over: the accessibility tree cannot be read in-process without the permission this project refuses to request, and Dynamic Type is inert on macOS — which makes the pseudo-locale test the only check invariant Y3 has. **P6's interface is complete**, and the pseudo-locale test that closed it caught the product truncating a Turkish group name in a 130 pt column that needed 144 — a live defect, not a hypothetical, fixed by re-measuring the table rather than by eye. The check derives its inventory from the views' own declarations so it cannot go stale, preserves format specifiers where the platform's own pseudo-localization corrupts them, and holds a 1.4× expansion budget with 2× kept as a diagnostic that is reported and never failed. **P6 is `BLOCKED` rather than `DONE`, deliberately:** every sub-task is complete, but the acceptance criterion "every critical flow completable with VoiceOver" cannot be evidenced from inside the project — driving a screen reader needs the permission I2 forbids — so it is now manual task M09, and `make next` steps over it to P7. 224 tests, 11 gates. **P7 has begun, and its first task found that `make test` could not fail:** both it and `make build` piped into `tail`, so `swift test`'s exit status was discarded and a failing suite exited 0 — in CI as well. Fixed and proven in both directions, and it explains the `HardwareKit error: fatalError` P6.10 recorded as unexplained. **The product now notifies**, with the noise control as tested `Core` maths: a suppression window that cannot extend itself, coalescing that cannot bury a panic behind a profile change, quiet hours that span midnight, and one trigger — the panic — that survives all five mechanisms stacked against it. Nothing asks for the notification permission until the user turns the switch on, and a refusal turns it back off. 251 tests, 11 gates. **Measurements can be recorded**, and the part that had to be right is: the disk ceiling is a pure decision over file metadata, so "does 500 MB hold" is a test rather than half a gigabyte of writing, and it is proven on a real disk too. Retention is a preference and the ceiling is a promise, in that order — and the file being written is never deleted, whatever either says. The settings window is finally the **seven tabs** the blueprint asks for. **The P7.01 `make test` fix immediately earned itself:** an intermittent `HardwareKit error: fatalError` that used to print and exit 0 now fails the build, so it is a tracked blocker (P7.12) instead of a mystery. 276 tests, 11 gates. **All six diagnostic checks exist**, and the two new ones were designed from probing the machine rather than from the specification: battery figures are published in the IO registry and answer on desktops too, so "this Mac has no battery" is a definite answer rather than a failed read; drive **wear** is not readable without a privilege this project will not ask for, and the check says so as its own finding instead of leaving the gap to be inferred. The two notification triggers P7.01 shipped inert now fire. 285 tests, 11 gates. **The command line tool is complete**, and a terminal command was measured moving a real fan from 1000 to 2385 rpm through the app's own arbitration — then handing it back to firmware on quit. A profile chosen from the CLI is deliberately **live only**: P6.14 found that a stored manual selection vetoes every trigger forever, so persisting one from outside would have re-introduced that bug where nobody would look. `import` validates before it writes and writes back the *loaded* model, so the file on disk cannot disagree with the settings in force. **The support report is in, and it is an allowlist rather than a dump**: the drive serial that sits beside its model in the IO registry, the account name inside every path and the machine name that is usually a person's are all absent by construction, and the drill proves it using this machine's own values as the needles — reading the serial expressly to check the serial did not survive. There is no submission path at all, and `gate-privacy` is what holds that promise. **The product speaks five languages.** 445 strings × 5, with Russian's four plural categories, Spanish's two and Chinese's none — the last being correct rather than a shortcut. Both filed as P7.14. **An unrecognised sensor is now one click from a filed report** — and the payload is an allowlist for a sharper reason than the support report's: a pre-filled issue URL reaches the server **on page load, not on submit**, so "the user can review it" is not a privacy control and only four facts are permitted to travel, each a class of machine rather than an instance. The `--report-drill` runs this machine's own account name, machine name and drive serial against the built URL, and the branch that would have skipped those assertions on a fully classified Mac was closed rather than left green. Writing it found `docs/product/scope.md` still filing three shipped-or-scheduled features under "Next wave", one of which shipped a whole phase ago. **And the CLI defect P7.08 uncovered is closed:** a sentence written for a person is no longer the input to a decision — `--helper-status` emits a translated line *and* a token, and the two are formatted and parsed in one shared place so neither binary writes the other's literal. Measured on this Turkish Mac: `boreas profile Quiet` now drives the real fan **1000 → 1710 rpm** from a terminal, which was impossible an hour earlier. The first regression test written for it was a **fake gate** — the fix had made the old bug accidentally harmless, so the deliberate violation passed — and it was replaced with one that tests the defect class instead: the same flag under two locales must give an identical token and a different sentence. **And CI is green for the first time since 2026-08-04**: a fresh clone could not generate the Xcode project at all, because the git-ignored `Local.xcconfig` is named by `project.yml` and XcodeGen refuses a spec without it — so the app build, the layout test and the CLI build had not run remotely for six days while 27 run logs honestly recorded `make check` green. The gates run offline and nothing ever asked about the remote; `make ci-status` and a `BOOT.md` snapshot line now do. **And `--curve-drill` no longer fails for being right:** it used to rebuild its expectation from a temperature the fan had already changed, so it was reliable only where the test curve saturates and missed by ~370 rpm on the slope. It now asks provenance and tracking separately — the command must fall inside the band the edited curve spans over the temperatures actually observed, and the hardware must track the cycle-late samples P6.09 already collects. Proven across six hardware runs and by removing the edit to watch the band reject it. **P7 is feature-complete:** automation hooks shipped — webhook and command, each behind its own switch, with the command hook proven to leave no process behind until permitted, and the payload carrying stable identifiers rather than translated ones because P7.14's lesson was three tasks old and about to be repeated. **H6 now covers four of the five languages** instead of one; Cyrillic and CJK had been undetectable since P7.06, and quoting a translation as evidence is now a declared, counted exemption rather than a hole. **And the `fatalError` that four tasks hunted for was never a crash:** `error: fatalError` is what SwiftPM prints when a package fails to *build*, and both `make test` and `make build` summarised with the last `error:` line, which is always that trailer — so a compile failure read as a runtime fault in the hardware layer. Reproduced on demand, both targets now name the file, line and column, and the two standing hypotheses (a nondeterministic hardware path; racing SwiftPM invocations) are disproven and written down as dead. 313 tests, 11 gates, 25 CLI checks, 448 strings × 5. ## The "do the next task" algorithm

1. Run the `BOOT.md` health snapshot. **If a gate is red, fix that first.**
2. Find the lowest numbered incomplete phase in the status summary above.
3. Are that phase's dependencies `DONE`? If not, move to the dependency.
4. Pick the first unchecked atomic task in the phase.
5. If the task depends on a manual task, **skip it, take the next one.** A blocker never freezes the work.
6. Do the task. **Run** the verification commands and read the output.
7. Pass the `AGENTS.md` §8 Definition of Done list.
8. Close the session: checkbox + status summary + run log — **in the same change**.

- [x] **P7.11 — `--curve-drill` measures the wrong instant.** Found in P7.01. Its pass condition compares the settled fan speed against the curve's expectation at the temperature measured *afterwards* — but the fan's own cooling has already moved that temperature, so on the curve's slope the fan legitimately sits ~370 rpm above the recomputed expectation and the drill fails. Measured at three temperatures: 14 rpm out at 52.6 °C (where the steep test curve saturates and the fan is simply pinned at its ceiling, proving little), 371–379 rpm out at 59–64 °C. Fix with the P6.09 insight — compare against the temperature that *drove* the final target, sampled a cycle late. The 350 rpm tolerance is a coincidence of where the curve saturates and should fall out of the rework.
- [x] **P7.12 — `HardwareKit error: fatalError`, now build-breaking.** Recorded as unexplained in P6.10, recurred in P7.02, and **P7.01 changed its severity**: `make test` used to print it and exit 0, so it was cosmetic; now that the exit status is honoured it fails the build and would fail CI intermittently. What is known: not reproducible in 8 deliberate attempts (3 direct, 2 after `xcodebuild`, 3 through the full P7.02 command sequence); HardwareKit passes standalone every time; its tests touch **no hardware** — the only `SMCConnection` use is static `encode`/`decode`, so the P6.10 hypothesis of a nondeterministic hardware path is ruled out; the single `precondition` in `SMCConnection.call` guards an internally built buffer, not hardware data, so it is not a §6.3 violation and not obviously reachable. The remaining hypothesis is still two SwiftPM invocations over one build directory. **P7.03 did the groundwork:** `make test` now prints the **full captured output** on failure instead of the `grep`-filtered tail, proven with a deliberate failure (631 lines where there had been one) — so the next occurrence is a diagnosis rather than another mystery. It recurred once more during P7.03 and again refused to reproduce (5 direct runs, 6 through `make test`, all green).
- [x] **P7.10 — Automation hooks.** Webhook and shell command, per [ADR 0015](docs/architecture/adr/0015-automation-hooks-not-email.md) and `docs/operations/notifications.md`. **Found unowned in P7.01:** the feature is documented, decided by an ADR, and `make gate-privacy` already allowlists `App/Sources/Automation/` for network access — a gate written for code no task was scheduled to produce. Command hook off by default, explicit warning on enabling, user privileges only (never the daemon), timeout and concurrency limit. Includes correcting the `shortcuts` on-disk encoding to a JSON object with tolerant decoding, since it is the same kind of defect in the same file — see `docs/architecture/configuration.md`.
- [x] **P7.14 — `boreas profile <name>` is broken on every non-English system, and `--auto` reports success into the void.** Found in P7.08 by running the commands the troubleshooting document tells users to run. **Two defects in one function, `CLI/Sources/ProfileCommand.swift`.** (1) **`helperIsInstalled()` decides by matching English prose**: it calls the app's `--helper-status` and returns `answer.contains("enabled")`, but that answer is `HelperInstaller.State.summary`, which is localised. Measured on this machine, same helper, same second: `--helper-status` → `helper status: etkin` under the system locale and `helper status: enabled` under `-AppleLanguages '(en)'`. So `boreas profile Quiet` exits 1 with *"the fan control helper is not installed"* while `boreas status` on the same machine reports it enabled — one binary, one truth, two answers. **It is wrong for four of the five shipped languages**, and it is the P7.06 bug class (a translation breaking a code path that never mentioned translation) moved into the CLI. The fix is not a wider `contains`: `--helper-status` should return a stable machine-readable token and both call sites should read that, leaving the localised text for humans. (2) **`--auto` posts unconditionally and always returns 0**, printing "asked the running app to hand the decision back" even with no app running — proven with `pgrep` showing no process. The named path five lines below it already guards, with the comment *"A selection that silently did nothing would leave the user with no way to tell why"*; the `--auto` branch never got the same treatment. **Why `make cli-test` passes 19/19 on this very machine:** it never activates a real profile. It asserts that `profile <unknown>` is refused — which passes for the right reason — and never notices that `profile Quiet` is refused for the wrong one. The regression test has to activate a configured profile, not only reject an unconfigured one.
- [x] **P7.15 — CI had been red for 27 consecutive runs and nothing surfaced it.** Found 2026-08-10 when the project owner asked why CI reported failure. `project.yml` names `Local.xcconfig` as the config file for **both** configurations; the file is git ignored because it carries a team identifier, and XcodeGen refuses a spec whose config file is absent. So `make generate` failed on **any fresh clone**, CI included — the job died before ever reaching Build app, the layout test or the CLI build. It began at the commit that introduced signing (2026-08-04 01:10) and the last green run was 2026-08-04 00:51. Fixed in `make generate`, not in the workflow, because a new contributor hits exactly the same wall on their first clone; the seed is announced rather than silent, since an empty `DEVELOPMENT_TEAM` is why the privileged helper will not run ([ADR 0019](docs/architecture/adr/0019-signing-identity-deferred.md)). **The deeper failure is the process one:** every run log from P4 onward recorded `make check` green and none of them looked at CI, because nothing in `BOOT.md` or the Definition of Done ever asks. A `make ci-status` target and a `BOOT.md` snapshot line now do.
- [x] **P7.13 — `gate-language` only detects Turkish, so H6 is unenforced for three of the five languages.** Found in P7.07. The gate scans for the six Turkish-only letters named in `scripts/gates/check-language.sh` and nine Turkish function words; **Cyrillic and CJK are not detected at all**, and Turkish's own `ü`/`ö`/`ç` are deliberately absent because they false-positive on German and French. Consequence measured while adding `TRANSLATORS.md`: that file is listed in the gate's exclusion regex per [ADR 0021](docs/architecture/adr/0021-english-only-repository.md), **but the exemption is inert** — its Cyrillic, CJK and the word "Türkçe" are all invisible to the gate, so it would have passed either way. Since P7.06 the repository holds three languages the gate cannot see. **The fix is not a one-line pattern**, which is why this is its own task: a Cyrillic/CJK rule goes red immediately on five files that legitimately *quote* a translation as evidence — `SystemSummary.swift`, `SensorTable.swift` and `CurvePointTable.swift` record measured Russian label widths in comments, `TODO.md` holds P7.06's run log, and `docs/development/localization.md` shows the plural examples. Whether quoting a translation is permitted under H6 belongs in an ADR 0021 addendum alongside the exception table, not in a gate tweak. **Method note for whoever writes it:** a bracket range such as `[А-Яа-яЁё]` passed to `grep` under the C locale is matched **byte-wise**, and the resulting range swallows the em dash (`E2 80 94`) this repository uses everywhere — the first scan attempted in P7.07 reported all 276 files as hits. Use `python3` with explicit UTF-8, as `check-catalog.py` already does, rather than `grep` ranges.

| YYYY-MM-DD | <session> | P<n>.<nn> | DONE/BLOCKED | <what was done and WHY it was done that way; unexpected findings> | <commands + PASS/FAIL/NOT RUN+reason> | <files> | <risk> | Next: P<n>.<nn> |

**Rules:**
- Never hesitate to write `NOT RUN` — "I wrote it, it probably works" makes the system a liar
- Record the unexpected finding **with its evidence**, so the next session does not fall into the same trap
- `Handoff` must be a single, definite task
