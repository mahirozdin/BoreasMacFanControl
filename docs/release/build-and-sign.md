# Build, Signing and Distribution

> Last updated: 2026-08-12 — P8.09
> Source: blueprint §16 · Decision: [ADR 0017](../architecture/adr/0017-distribution-channels.md)

## Local build

```bash
make bootstrap
make generate
make build
```

## Signing chain

1. Signing with the **Developer ID Application** certificate — the application, the daemon and the CLI **each separately**
2. **Hardened Runtime** on; entitlements kept to the minimum
3. Notarization with `notarytool`
4. Ticket stapling with `stapler`

**If notarization fails, the release is not published** — CI breaks at this step.

Secret values (the certificate, the API key) come in through GitHub Actions secrets. **Keys never enter the repository** — `.gitignore` and the `BOOT.md` health snapshot check for this.

## Distribution channels

| Channel | Priority |
|---|---|
| **Homebrew Cask** (`brew install --cask boreas`) | Primary |
| **GitHub Releases** (signed, notarized DMG + SHA-256) | Primary |
| Sparkle in-app updates | Deferred (`ARCHITECTURE.md` §12) |
| Mac App Store | ❌ The sandbox does not allow a privileged daemon |

## Versioning

- **Semantic Versioning** (`MAJOR.MINOR.PATCH`)
- `CHANGELOG.md` — Keep a Changelog format
- Tags: `v1.0.0`
- **The configuration schema is versioned separately**; a schema break requires MAJOR

## Release gates

No release ships until every gate in `ARCHITECTURE.md` §10 is green. In short: all invariant tests · `Core` coverage ≥ 85% · `make check` green · the `kill -9` and sleep smoke tests on real hardware · notarization · 5 languages complete + the pseudo-locale test · an honest README "tested hardware" section.

## As built (P8.01–P8.04, P8.09)

| Step | Where | Proven |
|---|---|---|
| Sign | [`scripts/sign.sh`](../../scripts/sign.sh) | On this machine and in CI |
| Disk image | [`scripts/make-dmg.sh`](../../scripts/make-dmg.sh) | Built, signed, hashed |
| Notarise + staple | [`scripts/notarize.sh`](../../scripts/notarize.sh) | `Accepted`, stapled, `spctl` → `source=Notarized Developer ID` |
| Cask | [`scripts/make-cask.sh`](../../scripts/make-cask.sh) | Generated from the image |
| Automation | [`.github/workflows/release.yml`](../../.github/workflows/release.yml) | Full chain green in one job |
| Release gates | [`scripts/release-gates.sh`](../../scripts/release-gates.sh) | 5 of 8 automatic; 3 need a person |

**Signing order is not a style choice.** The helper lives inside the application
bundle, so it is signed first; signing the outer bundle before its nested code
invalidates the outer signature. Hardened Runtime and a secure timestamp on
everything, both required by notarisation.

**The identity is resolved, not named.** This team holds two Developer ID
certificates with identical subjects, which makes `codesign -s "<name>"`
ambiguous; the hash is looked up, the choice is logged, and `SIGN_IDENTITY` pins
it if one is ever revoked.

**Two ways into the release job.** A `v*` tag builds, signs, notarises, staples
and publishes. `workflow_dispatch` runs the identical chain and stops at a build
artifact — which is how the chain was proven without publishing a version of the
product that is not ready to be published.

## Submitting the Homebrew cask (M05)

The cask file is generated by the release job; **submitting it is manual and
always will be**, because it means opening a pull request against somebody
else's repository. `boreas` was confirmed unused in both `homebrew-cask` and
`homebrew-core` in P8.07.

**Route 1 — your own tap.** No notability requirement, works the day a release
exists. Create a repository named `homebrew-boreas`, put the generated
`boreas.rb` in `Casks/`, and the install becomes:

```bash
brew tap mahirozdin/boreas
brew install --cask boreas
```

**Route 2 — the official `homebrew-cask`.** Reaches everybody without a tap, but
Homebrew applies notability requirements to new casks, so this is worth doing
once the project has users rather than on day one. Fork the repository, drop the
generated file in `Casks/b/`, then:

```bash
brew audit --new --cask boreas
brew install --cask ./Casks/b/boreas.rb   # test the real install
```

Either route needs a **published** release first: the cask's `url` points at a
release asset and its `sha256` is that asset's hash.
